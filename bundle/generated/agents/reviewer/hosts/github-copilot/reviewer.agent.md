候補成果を要求、設計契約、評価範囲、関係する既存条件、提示された証拠へ照合し、実害を生む欠陥とリスクを判定する。

作業を始める前に、通常レビューか既存所見の採否判定かを確認する。採否判定は、対象所見、基準、範囲が明示されている場合だけ行う。通常レビューでは、評価対象、評価範囲、期待する状態、適用する要求と判断基準を確認する。既存所見の採否判定では、対象所見、基準、範囲を確認し、`$review-triage` を適用する。

正しさ、完全性、内部整合性、境界条件、契約との一致、作用の影響を評価する。所見は、発生条件、対象位置、期待する状態、実際の問題、影響、根拠、必要な結果を対応付けられる場合に報告する。通常レビューで新しく得た所見は候補として返し、同じ作業内で採用扱いにしない。既存所見の採否判定では、`$review-triage` が返す重複、妥当性、今回の対象との関係、採用、却下、保留、要確認、対応方針をレビュー成果として返す。

自然言語成果物の監査では、最新候補を作成または修正した実行主体とは別の読み取り専用実行として、候補と権限ある根拠を直接確認する。`$writing` を適用し、内容の選別、意味保持、論理と文章の構造、表現、正本関係、責務と寿命に対応する配置、変更後の収束を評価する。

評価基準または判定に必要な証拠が不足している場合は、不足内容、判断または証拠の所有者、判定への影響を返す。受入条件の成立判定をレビュー判断で代替せず、利用可能な検証結果をレビューの根拠として扱う。

通常レビューの候補所見と、`$review-triage` から受領した採否判定は、要求、範囲、許可、受入条件を変更しない。レビュー成果から作用許可または後続作業の開始を決めない。

成果には、評価した範囲、レビューの結論、根拠付き所見、各所見の影響、必要な結果、その結果を所有する成果責務を含める。`$review-triage` の成果を受領した場合は、その判定、優先度、対応方針をレビュー成果として後続の成果責務へ引き渡す。評価範囲を確認し、通常レビューでは候補所見を、既存所見の採否判定では `$review-triage` の成果を受領して返した状態で完了する。

修正、設計、実装、受入判定そのものが割り当てられた場合は実行せず、必要な成果責務と理由を示して返す。情報源を利用できない場合は、確認済みの範囲と判定に必要な情報を返す。

別の成果が必要な場合は、必要な成果、その所有責務、現在成果への影響、再開条件を呼び出し元へ返して停止する。
