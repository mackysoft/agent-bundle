# interactive-session-execution

## 目的

凍結済みの対話セッション実行・証拠契約 envelope の execution 部分を、許可された対象に対して一回だけ履行する。各段階の操作、待機、直接観測、媒体、停止、reset、後始末を生記録として残し、後続作業が内容を補完せずに参照できる生セッション結果を返す。

## 責務境界

このスキルは、凍結済み execution・evidence envelope の execution 部分の実際の操作、`action → wait → observe`、直接観測、媒体取得、生記録の保存、停止、resetまたは隔離、後始末、結果の状態を所有する。envelope の evidence requirements 部分は、必要な生記録と媒体を取得するために参照するが、要求対応や証拠の解釈は行わない。

経路またはリスクの選定、比較基準、比較結果、再現の意味付け、候補所見、原因、設計またはゲーム領域の解釈、レビュー、受入判定、外部投稿は扱わない。実行契約にない操作、観測、証拠要件を追加しない。

## 入力契約

実行前に、次を追える凍結済み execution・evidence envelope を受け取る。

| 入力 | 内容 |
| --- | --- |
| envelope 識別 | 契約ID、revision、digest、作成時点。 |
| execution 部分 | 対象、版、実行個体、環境、開始状態、操作主体、許可された作用、順序または経路、各待機条件、観測点、実行上限、停止条件、resetまたは隔離、後始末、終了状態の確認方法。 |
| evidence requirements 部分 | 安定した要求ID、必須性、必要な生記録と媒体、時点、成立条件、有効条件、無効化条件、保存先、秘匿情報の扱い、共有可能な範囲。 |

契約ID、revision、digest、execution 部分、または evidence requirements 部分の必要な項目を確認できない場合は、対象へ作用しない。不足と影響する実行範囲を生セッション結果に残す。

## フロー

### Phase 1: envelope と開始条件を確認する

契約ID、revision、digest、対象版、実行環境、開始状態、操作主体、現在の許可、証拠保存先、実行上限、停止条件、安全な終了処理を確認し、開始時点と確認結果を記録する。

必須入力、実行能力、現在の許可、開始状態、証拠保存、または安全な終了処理を利用できない場合は、結果状態を `blocked` とし、不足、阻害理由、影響する実行範囲を記録して Phase 3 へ進む。開始条件が揃った場合は Phase 2 へ進む。

### Phase 2: 契約済みの段階を反復実行する

envelope の execution 部分に定められた各段階について、次を順番に行う。

1. 次の操作に必要な入力、実行能力、現在の許可、証拠保存、安全な終了処理を再確認する。いずれかを利用できない場合は、結果状態を `blocked` とし、阻害理由と未実施範囲を記録して Phase 3 へ進む。
2. 停止条件、実行上限、安全上継続できない条件、対象状態の異常が成立していないことを確認する。成立している場合は、結果状態を `stopped` とし、停止理由と未実施範囲を記録して Phase 3 へ進む。
3. `action → wait → observe` の順で履行し、操作、待機条件と結果、直接観測、時点、状態、媒体参照、契約または許可からの逸脱をそのまま記録する。
4. 観測後に停止条件、実行上限、安全上継続できない条件、対象状態の異常、契約または許可からの逸脱を確認する。成立している場合は、結果状態を `stopped` とし、停止理由と未実施範囲を記録して Phase 3 へ進む。成立していない場合は次の契約済み段階へ進む。

すべての契約済み段階を終えた場合は、結果状態を `completed` として Phase 3 へ進む。実行中に得た内容から比較、所見、原因、重要度、設計上の意味、受入可否を導かない。生記録を整理するために操作を再実行しない。

### Phase 3: 後始末を行う

対象へ作用し、契約上の後始末が必要な場合は、Phase 1 または Phase 2 で定めた結果状態が `completed`、`stopped`、`blocked` のいずれであっても、契約で許可され、現在も安全に実行できる reset、隔離、終了確認、媒体収録の終了を履行する。後始末の操作、待機、観測、残存状態を記録し、必要な終了処理と終了状態を確認できた場合は後始末状態を `completed` とする。必要な後始末を現在の許可または安全条件のもとで実行できない場合は、追加の作用を行わず、実行できない処理と残存状態を記録して後始末状態を `incomplete` とする。後始末を実行しても必要な終了状態を確認できない場合も `incomplete` とする。

対象へ作用していない場合、または契約上後始末が不要な場合は、後始末状態を `not-required` とする。Phase 2 で以後の操作を停止した場合も、契約済みの後始末は追加のテスト操作とみなさず履行する。後始末状態を定めた後、Phase 4 へ進む。

### Phase 4: 生セッション結果を確定する

生セッション結果には、受け取った envelope と同一の契約ID、revision、digest、対象と版、環境、開始状態、実施した段階ごとの `action`、`wait`、`observe`、時点、直接観測、媒体参照、逸脱、停止理由、実施済み範囲、未実施範囲、終了状態、後始末記録を含める。

結果状態は Phase 1 または Phase 2 で最初に到達した次の一つを保持する。後始末の成否によって結果状態を置換しない。

| 状態 | 到達条件 |
| --- | --- |
| `completed` | 凍結済み envelope の execution 部分の操作、必要な観測、各観測後の停止確認をすべて終え、停止事由がないことを確認した。 |
| `stopped` | 開始条件の成立後、`completed` を確定する前に、停止条件、実行上限、安全上継続できない条件、対象状態の異常、契約または許可からの逸脱を検出して停止した。 |
| `blocked` | 必須入力、実行能力、現在の許可、開始状態、証拠保存、または安全な終了処理を利用できず、開始または継続できない。 |

後始末状態は Phase 3 で到達した次の一つを保持する。

| 状態 | 到達条件 |
| --- | --- |
| `completed` | 必要な終了処理を実行し、契約で定めた終了状態を確認した。 |
| `incomplete` | 必要な終了処理または終了状態の確認を完了できない。 |
| `not-required` | 対象へ作用していないか、契約上終了処理が不要である。 |

## 完了条件

- 凍結済み execution・evidence envelope の識別子、revision、digestを生セッション結果から追え、受け取った値と一致する。
- 実施した各段階の `action → wait → observe` と直接観測、媒体参照を追える。
- 実施済み範囲、未実施範囲、停止または阻害の理由を追える。
- 結果状態と後始末状態が定まり、必要な終了処理の記録がある。
- 比較、候補所見、設計、レビュー、受入判定を生セッション結果へ混在させていない。
