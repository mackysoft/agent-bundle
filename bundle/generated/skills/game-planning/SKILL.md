# game-planning

## 目的
混在したゲーム企画依頼から、企画全体で共有する入力契約を作り、必要な専門作業を選択、反復、統合して、一つの企画成果へ到達させる。

成果は、企画の目的、対象範囲、制約、現在有効な決定、未解決の問い、専門作業ごとの入力と結果、採用に必要な判断、完了条件を追える企画成果である。

## 責務
このスキルは、次のゲーム企画全体の契約を所有する。

- 企画依頼を、専門作業へ渡せる入力契約にする。
- 入力契約から必要な専門作業と実行順を選ぶ。
- 専門作業の結果、仮定、未確認事項、相互依存を統合する。
- 企画上の再判断、専門作業の再適用、反復の終了を決める。
- 企画全体の成立状態、未解決事項、採用に必要な判断を返す。

企画を構成する判断の所有者を次のように定める。

| 判断または成果 | 所有者 |
| --- | --- |
| 企画全体の入力契約、専門作業の選択と順序、成果の統合、全体完了 | このスキル |
| コンセプト、プレイヤー活動、ルール、状態変化、体験へ至る定性的な因果 | `$game-design` |
| 固定ルールの定量モデル、成立範囲、支配条件、破綻条件、回復可能性 | `$game-balance-analysis` |
| 確認済みのゲーム上の意味から、提示、入力、情報階層、状態遷移への写像 | `$game-interface-design` |
| 探索または仮説検証のプレイテスト計画、実プレイの観測、結果状態 | `$playtest` |
| 企画候補の採用状態 | 採用権限を持つ主体 |
| 技術実装、制作日程、要員配置、予算、事業計画 | それぞれの担当作業または権限主体 |

## 発火と直接適用
依頼の状態から、次の開始先を選ぶ。

| 依頼の状態 | 開始先 |
| --- | --- |
| 目的、対象範囲、制約、決定状態、未解決の問い、完了条件が混在または未確定である | このスキルで入力契約を作る。 |
| 複数の専門領域を同じ企画目的と制約の下で接続する | このスキルで専門作業を選択、統合する。 |
| 一つの専門作業の結果が別の専門作業または企画判断を変え得る | このスキルで反復を管理する。 |
| 目的、対象範囲、制約、必要な入力が確認済みで、一つの専門領域だけを扱う | 該当する専門スキルを直接適用する。 |

## 入力契約
次を企画全体の入力として受け取る。

- 企画として達成したい目的と対象範囲。
- 対象プレイヤー、プレイ条件、プラットフォーム、制作上の制約。
- 現在有効な企画上の決定、変更してよい範囲、維持すべき条件。
- 既存のゲーム設計、数値、インターフェース、観測結果、候補案。
- 未解決の問いと、それぞれが変える判断。
- 利用できる専門作業の入力、成果、根拠、実行上の制約。
- 成果物の利用者、形式、受け入れ条件、採用または追加判断の権限者。

入力不足が企画の方向、専門作業の選択、受け入れ条件のいずれかを変える場合は、状態を `企画判断待ち` とする。この状態では、不足する企画上の判断、判断主体、影響する専門作業と問いを返す。

## フロー

### Phase 1: 企画の入力契約を作る
要求、観測、既存案、変更案、受け入れ条件、権限者が混在し、変更目的、対象範囲、許可、維持条件、完了条件の確定が必要な場合は、`$change-framing` を適用する。その成果を企画の変更契約として採用する。

複数の会話、議事録、仕様、成果物にまたがる命題について、現在の採用状態、適用範囲、関係、未確認事項の確定が必要な場合は、`$claim-grounding` を適用する。その成果を企画の根拠契約として採用する。

プレイヤー、キャラクター、ゲーム状態、資源、選択、画面、結果などの名称が複数の具体対象、単位、役割を覆い、専門作業の対象または関係を変える場合は、`$referent-modeling` を適用する。その成果を企画の対象契約として採用する。

入力契約には、少なくとも企画の目的、対象範囲、制約、現在有効な決定、未解決の問い、各問いが変える判断、完了条件、権限者を含める。専門作業に渡す問いは、その作業の入力と、結果を受け取る企画上の判断を対応させる。

### Phase 2: 専門作業を選択して実行する
入力契約にある問いごとに必要な専門作業を選ぶ。選んだ下位スキルの `入力契約` と `開始状態` に、企画の入力を対応付ける。表の「渡す入力」は最小集合であり、下位スキルが作業種別と対象に応じて求める項目も渡す。

| 問いまたは必要な成果 | 適用する専門作業 | 渡す入力 |
| --- | --- | --- |
| 狙う体験、プレイヤー活動、ルール、状態変化、結果の意味、進行の因果を設計または評価する | `$game-design` | 作業種別、企画目的、設計上の問い、対象範囲、設計を委ねた項目、制約、変更範囲、維持条件、受け入れ条件、対象プレイヤーとプレイ条件。更新または評価では、現在有効な設計と、観測、原因仮説、候補、未確認事項の地位。 |
| 固定されたルールの数値関係、成立範囲、支配条件、破綻条件、回復可能性を調べる | `$game-balance-analysis` | 定量的な問い、結果が変える設計判断、意図する関係または目標状態、意味と適用範囲が固定されたルール、状態遷移、初期条件、時間幅、比較する戦略またはシナリオ、プレイヤーが利用できる情報、各入力値の地位と根拠、実行上の制約。 |
| 確認したゲーム上の情報、活動、結果の意味を、提示、操作、情報階層、画面状態へ写像する | `$game-interface-design` | 作業種別、インターフェース上の問い、対象範囲、変更範囲、プレイヤーの判断、活動、実行できる行為と成立条件、ゲーム上の情報、状態、結果の意味と利用可能時点、プラットフォーム、表示領域、入力機器、利用条件。更新または評価では、既存インターフェースと維持契約、確認済みの観測。 |
| 実際のプレイヤーの理解、選択、行動、感情を探索し、または未検証の仮説を確かめる | `$playtest` | 計画、実行、結果評価の作業種別、観測目的、設計上の問い、結果が変える設計判断、対象版とプレイ範囲、対象プレイヤーとプレイ条件、確認済みのルールと既存観測、必要な許可。計画または実行では、役割、記録手段、環境、資源上限。仮説検証を求める場合は、仮説、競合する説明、識別観測、事前基準。実行または結果評価では、使用版、実施範囲、記録。元の計画を利用できる結果評価では、その計画と逸脱。 |

専門作業の前提が不足する場合は、前提の性質から次の状態を選ぶ。

| 状態 | 到達条件 | 次の作業と成果 |
| --- | --- | --- |
| `専門入力待ち` | 前提の意味を、責務表にある別の専門作業の成果として確定できる。 | 先に適用する専門作業、不足入力、その結果が影響する問いを返す。 |
| `企画判断待ち` | 前提が目的、許可、採用状態、維持条件など、権限ある主体の企画判断を必要とする。 | 判断主体、判断内容、その判断が影響する専門作業と問いを返す。 |

専門作業の候補、分析結果、プレイテスト結果は、採用権限を持つ主体が企画判断に使う材料として統合する。採用判断を受け取った候補には、候補識別子、状態、判断主体、判断根拠、状態による後続処理を対応させる。

| 候補状態 | 到達条件 | 後続処理 |
| --- | --- | --- |
| `採用` | 採用権限を持つ主体が、適用範囲とともに候補を現在有効な決定へ含めた。 | 入力契約を更新し、影響する専門作業と企画成果を再評価する。 |
| `不採用` | 採用権限を持つ主体が、適用範囲とともに候補を現在有効な決定から外した。 | 判断根拠を保持し、候補に依存する作業を更新する。 |
| `保留` | 採用権限を持つ主体が、追加判断または証拠を必要とした。 | 必要な判断または証拠、その所有者、影響する問いを未解決事項へ追加する。 |

### Phase 3: 結果を統合して反復する
各専門作業について、入力契約、結論または候補、前提、未確認事項、結果によって変わる企画上の判断を対応させる。

結果間に競合がある場合は、競合する入力契約、前提、企画上の決定を特定する。解消先を、必要な専門作業の再適用または権限ある企画判断へ定め、影響する成果を再評価する。

目的、対象範囲、制約、完了条件に必要な問いを、次のいずれかへ対応させる。

- 結論。
- 採用判断に使う候補。
- 必要な専門作業と入力。
- 権限ある主体が判断する未解決事項。

新たな問いが生じた場合は、問いが変える判断と必要な入力を入力契約へ追加し、Phase 2 に戻る。追加後に新しい判断、候補、未確認事項が生じる間は反復する。追加後の対応が既存の状態と同じ場合は反復を終了する。

### Phase 4: 企画成果を返す
反復終了時の状態を次から選ぶ。

| 状態 | 到達条件 | 成果 |
| --- | --- | --- |
| `企画判断待ち` | 企画目的、許可、採用状態、維持条件など、権限ある主体の判断が次の作業を変える。 | 判断主体、判断内容、影響する専門作業と問い。 |
| `専門入力待ち` | 別の専門作業が所有する前提の成立により、対象の専門作業を開始または再開できる。 | 先に適用する専門作業、不足入力、影響する問い。 |
| `企画成果` | 必要な問いが、結論、候補、必要な専門作業、権限ある判断のいずれかへ対応し、現在の入力契約で反復が終了した。 | 依頼に必要な企画全体の成果。 |

`企画成果` では、依頼に必要な項目を次から選び、一つの成果として統合する。

- 企画の目的、対象範囲、対象プレイヤー、プレイ条件、制約。
- 現在有効な決定、未解決の問い、変更してよい範囲、維持する条件。
- 適用した専門作業と、それぞれの入力、結果、前提、未確認事項。
- 専門作業の結果を接続した企画上の結論または候補。
- 候補識別子、候補状態、判断主体、判断根拠、状態による後続処理または未解決事項。
- 採用、追加調査、追加プレイテスト、専門作業の再適用に必要な判断と権限者。
- 完了条件に対する成立状態と、未達の場合に残る作業。

企画成果を文章として表す場合の媒体、成果物の責務、正本、配置、文章構造、文体には `$writing` を適用する。

## 完了条件
共通して、状態が `企画判断待ち / 専門入力待ち / 企画成果` のいずれかに定まり、状態に対応する成果がある。

`企画判断待ち` では、判断主体、判断内容、その判断が影響する専門作業と問いを追える。

`専門入力待ち` では、先に適用する専門作業、不足入力、その結果が影響する問いを追える。

`企画成果` では、次を満たす。

- 企画の目的、対象範囲、制約、現在有効な決定、未解決の問い、完了条件を追える入力契約がある。
- 各専門作業が、成立した入力と、結果を受け取る企画上の判断を持つ。
- 各領域判断が、責務表で定めた所有者の成果へ追跡できる。
- 専門作業の結果、前提、未確認事項、相互依存を追える。
- 結果の競合または不足が、必要な専門作業または権限ある企画判断へ対応している。
- 各候補の識別子、状態、判断主体、判断根拠、後続処理または未解決事項を追える。
- 必要な問いが、結論、候補、必要な専門作業、権限ある判断のいずれかへ対応している。
- 企画成果が、依頼された利用者と完了条件に必要な情報を含む。
