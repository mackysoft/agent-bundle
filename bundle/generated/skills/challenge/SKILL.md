# challenge

## 成果責務

目的、要求、権限ある規範、局所文脈に照らして、成果物、設計、コード、構造上の選択の存在理由を問う。対象の選択を支える根拠、説明されていない部分、より小さい反実仮想、その影響、判断に必要な問いを対応付け、採否前の異議形成結果として返す。

異議を構成できる場合は異議候補を返す。評価範囲の選択が確認済みの根拠で説明される場合は、確認範囲を伴う候補なしの結果を返す。

## 入力

対象、評価範囲、目的、要求、適用される規範、局所文脈、タスク理由、維持する契約を入力として使う。

## フロー

### Phase 1: 評価基準を確定する

入力に含まれる命題の権限、採用状態、情報状態、適用範囲を確認する。入力から直接判定できない場合は `$claim-grounding` を適用する。

各根拠を、権限ある方針または契約、採用済み判断、現状観測、ヒューリスティックまたは好み、例、未確認情報のいずれかの役割で保持する。現在の実装や成果物は現状観測として扱い、専門領域の規則、設計判断、コード上の契約、文章上の判断は、その成果が持つ権限、状態、範囲を保持して使う。

対象と評価範囲を特定できる場合は、確定した評価基準と不足情報を分けて Phase 2 へ進む。対象または評価範囲を特定できない場合は、不足する入力、異議形成への影響、再開条件を持つ停止状態を返す。

### Phase 2: 構造選択と根拠を対応付ける

対象を、存在理由を独立して問える構造選択へ分ける。要素の存在、長さ、重複、間接化、抽象化、責務分割、状態、依存関係、説明の追加から、目的または維持する契約への影響を個別に判断できる単位を選ぶ。

各構造選択を、目的、要求、権限ある規範、採用済み判断、維持する契約、確定済みの制約へ対応付ける。選択が必要になる条件、その条件を支える根拠、根拠で覆われない範囲を記録する。

評価範囲の各構造選択に対応を作成した状態で Phase 3 へ進む。新しい構造選択を確認した場合は、その選択についてこのPhaseの対応を追加してから Phase 3 を再開する。

### Phase 3: 異議候補を形成する

次のいずれかに該当する構造選択を異議候補の対象にする。

- 必要性を支える確認済みの対応がない。
- 対応する根拠の条件または適用範囲が評価対象を覆わない。
- ヒューリスティック、好み、例だけが必要性を支えている。

構造選択が必要な目的または契約と、より単純な形では成立しない条件を具体的な問いにする。根拠が不足または競合する場合は、判断を確定する情報、判断主体、確認先を問いへ対応付ける。

異議候補がある場合は Phase 4 へ進む。評価したすべての構造選択が確認済みの根拠で説明される場合は、各対応と確認範囲を候補なしの成果として Phase 5 へ渡す。

### Phase 4: より小さい反実仮想を構成する

確認済みの目的、要求、規範、契約、制約を維持する範囲で、対象を削除、短縮、統合、または直接化した反実仮想を構成する。複数の形が成立する場合は、変更する構造選択が最も少なく、影響を確認できる形を選ぶ。

反実仮想について、確認済みの維持事項、期待できる単純化の効果、確認済みの影響、未確認の影響を分ける。契約維持の判定材料が不足する場合は、維持可否を決める具体的な問い、必要な根拠、再評価条件へ変換する。

各異議候補を、反実仮想または維持可否を決める問いへ対応付けた状態で Phase 5 へ進む。追加の根拠によって構造選択の必要性が確定した場合は、その選択を Phase 2 の対応へ戻して成果状態を再判定する。

### Phase 5: 成果状態を確定する

説明されていない部分が残る場合は、異議候補を採否前の状態で返す。評価した構造選択の必要性が確認済みの根拠で説明される場合は、その対応と確認範囲を候補なしの結果として返す。

証拠十分性には、異議と反実仮想を支える確認済みの根拠が、評価対象の条件と範囲を覆う程度を記録する。異議候補の妥当性、優先度、重複、候補間または既存所見との関係、採用状態は、後続判断に必要な未決事項として保持する。

## 成果

利用する媒体に合わせて成果を構成し、次の対応を保持する。

- 対象となる構造選択と位置。
- 評価に使った目的、要求、規範、局所文脈、タスク理由、維持する契約。
- 構造選択を支える根拠、その種別と役割、採用状態、情報状態、適用範囲。
- 説明されていない部分と、それを確認する具体的な問い。
- より小さい反実仮想と、維持する確認済みの契約。
- 確認済みの影響、未確認の影響、証拠十分性。
- 不足する情報、必要な判断主体または確認先、再評価条件。
- 確認した範囲と、異議候補または候補なしの成果状態。

情報取得、専門判断、異議候補の採否、設計、実装、変更、受入判定の成果が必要な場合は、必要な成果、対象、現在の異議形成結果への影響、再開条件を後続作業への入力として返す。

## 完了条件

評価した各構造選択を、必要性を支える根拠、異議候補、具体的な問い、または候補なしのいずれかへ対応付ける。異議候補を確認済みの目的、要求、規範、契約、制約と、より小さい反実仮想へ追跡できる状態にする。根拠の役割と状態、確認済みと未確認の影響、証拠十分性、確認範囲、再評価条件を区別し、成果を採否前の状態で返して完了する。
