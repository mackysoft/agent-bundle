# gameplay-observation

## 目的

中立な観測要求をゲームプレイ観測の記録項目契約へ設計するか、汎用証拠パッケージを用いて、対象プレイヤーの情報境界、理解、認識した選択肢、選択、行動、ゲームの応答、本人報告を追えるゲームプレイ観測レコードへ対応付ける。

成果は、対象版、対象プレイヤー、プレイ条件、情報境界、実際の状況、理解、認識した選択肢、選択、行動、ゲームの応答、本人報告、証拠参照、適用範囲を追える構造化記録である。

## 責務境界

このスキルは、ゲームプレイ観測レコードの記録設計と、汎用証拠パッケージからのゲーム固有の記録項目への対応付けを所有する。

対象を実際に遊ぶこと、アプリの操作、媒体取得、reset、後始末は生セッション結果の実行側が所有する。証拠の出所、時系列、媒体参照を再構成しない。ゲーム設計上の原因、設計仮説の評価、改善案、採用判断、アプリの機能適合、レビュー、受入判定は扱わない。

## 入力契約

共通して次を受け取る。

- 作業種別: `記録設計` または `記録整理`。
- 観測契約ID、観測目的、成果の利用先、対象となる試作またはゲームと版。
- 対象プレイヤー、人数、経験、操作環境、プレイ時間など、記録の適用範囲を変える条件。
- 対象プレイヤーが各判断時点で利用できる情報と、観測者だけが利用できる情報の境界。
- 観測項目IDごとの対象、成立条件、観測単位、観測時点、必要な記録、必須性、証拠の有効条件と無効化条件。

`記録整理` では、同じ実行・証拠契約 envelope の契約ID、revision、digestを持つ汎用証拠パッケージ、そのパッケージ状態、情報源一覧、変更しない時系列索引、要求と情報源の対応、直接の適用範囲、不足、競合、未確認事項も受け取る。対象プレイヤーの理解、認識した選択肢、本人報告を表すには、その時点と状況に対応する直接の情報源を必要とする。

## 記録設計

`記録設計` では、各観測項目に次の記録欄と、名前空間付きのゲーム固有 evidence requirements を定める。これは独立した証拠契約ではない。execution・evidence envelope の設計責務が、同じ envelope の evidence requirements 部分へ、観測契約IDを名前空間として統合する。

| 記録対象 | 記録する内容 |
| --- | --- |
| 状況 | 開始状態、直前の出来事、判断時点、対象プレイヤーが利用できた情報。 |
| 理解 | 原因、結果、目的、操作について本人が述べた説明または予測と、その時点の行動。 |
| 認識した選択肢と選択 | 本人が認識したと述べた選択肢、実際の選択、変更、取り消し、選択までの経過。 |
| 行動とゲームの応答 | 行動の順序、時点、反復、変更、中断と、それに対するゲームの表示または状態変化。 |
| 本人報告 | 状況と時点に結び付いた本人の表現。観測事実とは別の欄に置く。 |
| 証拠 | 記録内容を直接示す情報源、参照、示せる範囲。 |
| 制約 | 介入、情報露出、逸脱、記録欠損、未実施範囲。 |

設計上の意味または期待方向を対象プレイヤーへ開示しない。追跡に識別子が必要な場合は、意味を含まない観測契約IDと観測項目IDを使う。

## 記録整理

`記録整理` では、汎用証拠パッケージの変更しない時系列索引と、`linked` の情報源だけを、各観測項目へ対応付ける。情報源が直接示さない理解、認識した選択肢、本人報告、時点、順序を補完しない。

観測項目ごとに、状況、情報境界、理解、認識した選択肢、選択、行動、ゲームの応答、本人報告、証拠参照、逸脱、適用範囲、未確認範囲を該当する範囲で記録する。予定外に得た事実は、元の観測項目へ無理に含めず、`未予定の観測` として同じ記録形式で分ける。

各観測項目の証拠状態は、次から一つを選ぶ。

| 証拠状態 | 到達条件 |
| --- | --- |
| `記録成立` | 必須欄を満たし、対象、条件、時点、直接証拠参照を追える。 |
| `対象範囲内で未観測` | 指定された経路または試行範囲を実施した直接記録があり、その範囲では対象事象を観測していない。 |
| `判別不能` | 関連する記録はあるが、パッケージの競合、不足、情報露出、介入、条件競合により内容を確定できない。 |
| `未記録` | 対応する経路を実施していないか、対応する直接記録と証拠がない。 |

## 成果契約

`記録設計` では、状態 `記録設計完了` として、観測契約ID、観測項目ごとの記録欄、名前空間付き要求ID、必須性、必要な生記録と媒体、時点、成立条件、有効条件、無効化条件を返す。この成果は execution・evidence envelope の設計責務へ渡し、統合済みの凍結済み envelope を受領するまで実行側へ渡さない。

`記録整理` では、観測レコード一式の状態を次から選ぶ。

| 状態 | 到達条件 |
| --- | --- |
| `reportable` | 必須の観測レコードが `記録成立` または `対象範囲内で未観測` であり、パッケージの出所、適用範囲、証拠参照を追える。 |
| `partially-reportable` | 一件以上の観測レコードを報告へ利用できるが、ほかの必須項目が `判別不能` または `未記録` である。 |
| `insufficient-evidence` | 要求された観測について、起票または報告へ利用できる観測レコードを作れない。 |

各観測レコードには、レコードID、観測契約ID、観測項目ID、証拠パッケージと同じ execution・evidence envelope の契約ID、revision、digest、対象版、対象プレイヤー、プレイ条件、情報境界、状況と時点、理解、認識した選択肢、選択、行動、ゲームの応答、本人報告、証拠参照、証拠状態、逸脱、適用範囲、未確認範囲を該当する範囲で含める。

## 完了条件

- `記録設計` では、各観測項目の記録欄、必須性、証拠要件、有効条件、無効化条件を追える。
- `記録整理` では、各観測レコードを汎用証拠パッケージの変更しない時系列索引と直接証拠へ追える。
- 対象プレイヤー、情報境界、理解、認識した選択肢、選択、行動、ゲームの応答、本人報告を混同しない。
- 状態 `reportable / partially-reportable / insufficient-evidence` と不足する記録を追える。
- 操作、証拠再構成、設計解釈、因果、レビュー、受入判定を混在させない。
