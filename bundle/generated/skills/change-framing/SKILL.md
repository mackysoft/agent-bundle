# change-framing

## 目的
変更に関する権限ある根拠から、利用目的、変更目的、変更対象、適用範囲、契約変更、許可、受け入れ条件を再構成し、確定済みの実現制約および候補手段と分ける。

成果は、設計、実装、テスト、レビュー、検証が同じ変更意図と契約を使い、未確定の判断に依存する範囲を停止し、訂正時には影響する下流判断を再評価できるフレーミング結果である。

このスキルは、各判断項目の決定権限と根拠、項目間の対応、未確定判断、進行可能範囲を確定する。内部技術契約、コード構造、作業手順、テストケース、検証方法は、それぞれを所有する下流作業がフレーミング結果を使って決定する。

## 判断権限
各判断項目は、その内容を決定する権限を持つ主体が所有する。判断主体は、対象項目を決定できる権限、適用範囲、時点を示す根拠から確定する。同じ主体が複数の判断項目を所有してよい。

| 判断項目 | 所有する主体 |
| --- | --- |
| 利用目的 | フレーミング結果を利用する判断または成果物の責務を持つ主体。 |
| 変更目的 | 誰またはどの責務に、どの結果または価値を成立させるかを決定する主体。 |
| 変更対象 | 状態、振る舞い、責任、または関係を変更する具体対象を決定する主体。 |
| 適用範囲 | 変更と契約が成立する条件、版、期間、環境、責任範囲を決定する主体。 |
| 契約 | 対象の保証を所有する責務、またはその保証を決定する主体。 |
| 契約の変更関係 | 契約の追加、置換、終了、維持、または明示的な併存を決定する主体。 |
| 許可 | 対象または作用を管理し、誰が何をどの範囲で実行できるかを決定する主体。 |
| 受け入れ条件 | 変更結果を受け入れる責務を持ち、完了と判断する観測可能な状態を決定する主体。 |
| 確定済みの実現制約 | 技術、運用、互換性、依存関係などの実現方式を決定する主体。 |

## 成果の責務
フレーミング結果は、利用目的に必要な次の項目を持つ。

| 項目 | 内容 |
| --- | --- |
| 利用目的 | フレーミング結果を使う下流の判断、成果物、停止、または再評価。 |
| 変更目的 | 誰またはどの責務に、どの結果または価値を成立させるための変更か。 |
| 変更対象 | 変更によって状態、振る舞い、責任、または関係が変わる具体対象。 |
| 適用範囲 | 変更と契約が適用される対象、条件、版、期間、環境、責任範囲。 |
| 成立させる契約 | 変更後に成立させる、変更対象の観測可能な保証、制約、または失敗条件。新規追加と既存契約の置換後の契約を含む。 |
| 契約の変更関係 | 変更前の契約と変更後の契約の `追加 / 置換 / 終了 / 維持 / 明示的な併存` の関係。 |
| 維持する契約 | 変更前から有効で、変更後も成立させる保証、制約、または失敗条件。 |
| 作業対象外 | 今回の判断または作業に含めない対象、契約、条件、または範囲。 |
| 許可 | 許可された作用、実行主体、対象、適用範囲、成立条件、有効期間。 |
| 受け入れ条件 | 契約の追加、置換、終了、維持、または明示的な併存が完了したと判断できる観測可能な状態。 |
| 確定済みの実現制約 | 権限ある主体によって既に採用され、下流の手段選択を制約する方式、依存、互換性、運用上の決定。 |
| 候補手段 | 入力に含まれる未採用の実装案、構造案、作業案。 |
| 判断権限 | 各判断項目を所有する主体と、その権限、適用範囲、時点を示す根拠。 |
| 根拠対応 | 各項目を支える根拠化結果と指示対象の対応。 |
| 項目間の対応 | 変更目的、変更対象、適用範囲、契約変更、許可、受け入れ条件、実現制約、候補手段、下流判断の依存関係。 |
| 未確定判断 | 権限ある根拠から確定できない項目に必要な判断と、その判断に依存する項目。 |
| 再評価対象 | 訂正、置換、競合の解消によって見直す必要がある下流判断。 |
| 進行状態 | `進行可能`、`部分進行可能`、または `要確認`。 |

利用目的に不要な項目は成果へ追加しない。下流判断に必要な項目を根拠から確定できる場合は再構成し、確定できない場合は未確定判断へ対応付ける。単純な変更では、独立した文書や詳細な表を作らず、必要な項目だけを作業状態として保持する。

## フロー

### Phase 1: 利用目的と情報源を固定する
フレーミング結果を使う下流作業、対象とする変更、参照する要求、仕様、会話、観測、既存成果物の範囲を固定する。下流作業が必要とする判断項目を列挙し、各項目の判断主体を確認する。

各項目について、根拠の役割、採用状態、判断権限、適用範囲、訂正または置換の関係を入力から直接確定できる場合は、その内容を使う。これらを直接確定できない場合は `$claim-grounding` を適用し、フレーミング結果または下流判断を変える根拠化結果を保持する。

変更対象を表す語が複数の具体対象、役割、状態、条件を覆い、対応の違いが目的、契約、適用範囲を変える場合は、`$referent-modeling` を適用する。確定した指示対象の対応から、フレーミング結果を変える項目を保持する。

### Phase 2: 判断主体と根拠の役割を分ける
変更目的、変更対象、適用範囲、契約、許可、受け入れ条件、確定済みの実現制約について、それぞれの判断主体と権限根拠を対応させる。

- 現在の実装、出力、画面、テスト、文書は、現在の状態または既存契約を示す観測として、確認できた時点と適用範囲で使う。
- 例示は、権限ある根拠が支える対象、条件、範囲に対応する変更目的、契約、または受け入れ条件として使う。
- 実装案、構造案、作業案は、採用を決定する主体と採用状態に従い、採用済みの内容を確定済みの実現制約、判断前の内容を候補手段として扱う。
- 許可は、対象または作用を管理する主体が定めた実行主体、作用、対象、範囲、条件、有効期間として扱う。
- 受け入れ条件は、受け入れを所有する主体が定めた観測可能な完了状態として扱う。検証を所有する下流作業は、その状態を判定する方法を決める。
- 現状観測と要求は、それぞれの根拠の役割を保持したまま対応付ける。

### Phase 3: 確認済みの項目を再構成する
確認済みの判断権限、根拠、指示対象の対応から、利用目的に必要な項目を再構成する。

成立させる契約と維持する契約は、変更対象の利用者または隣接する責務が観測できる振る舞い、状態、不変条件、制約、失敗条件として表す。各契約には、変更前から有効な契約との `追加 / 置換 / 終了 / 維持 / 明示的な併存` の関係を対応させる。

適用範囲は、変更対象と契約が成立する条件を特定する。作業対象外に置いた既存契約は、その契約を変更する権限を持つ主体が終了または置換を決定するまで、維持する契約として扱う。

許可は、許可を決定した主体と、許可された実行主体、作用、対象、適用範囲、成立条件、有効期間へ追跡できる形で保持する。

受け入れ条件には、各契約変更の完了を判断できる状態を対応させる。検証方法、使用する道具、確認回数は、検証を所有する下流作業が受け入れ条件から決定する。

確定済みの実現制約は、それを採用した主体、対象、適用範囲へ対応させる。候補手段は依存する契約へ対応させ、採用判断に必要な材料として保持する。

変更目的から、変更対象、適用範囲、契約の変更関係、許可、受け入れ条件へ至る対応を保持し、実現制約、候補手段、下流判断を依存する項目へ対応させる。複数項目の対応を一意に追う必要がある場合は作業用の識別子を使い、利用者向け成果には求められた場合だけ識別子を示す。

確認済みの命題から項目を導出する場合は、必要な前提、根拠の組み合わせ、適用範囲を根拠対応に保持する。

### Phase 4: 未確定判断と進行状態を決める
利用目的に必要な項目を権限ある根拠から確定できない場合は、項目を補完するための未確定判断を作る。各未確定判断は、次の5項目を独立して持つ。

| 項目 | 内容 |
| --- | --- |
| 判断対象 | 決定する変更目的、変更対象、適用範囲、契約、許可、受け入れ条件、実現制約、または項目間の関係。 |
| 判断主体 | その判断を決定する権限を持つ主体。主体を特定できない場合は `未確認` とし、主体に必要な権限と責務、および特定に必要な情報を示す。 |
| 必要情報 | 判断主体が決定するために必要な事実、選択肢、制約、影響。 |
| 影響項目 | 判断結果によって変わるフレーミング結果の項目と下流判断。 |
| 回答先 | 判断結果を受け取り、該当項目と依存する下流判断を更新する作業または責務。 |

未確定判断から影響項目と下流判断への依存関係を項目間の対応へ加え、今回の利用目的と下流作業の範囲に対して進行状態を決める。

| 状態 | 条件 |
| --- | --- |
| `進行可能` | 今回の下流作業に必要な項目へ影響する未確定判断がなく、必要な変更目的、変更対象、適用範囲、契約変更、許可、受け入れ条件を根拠へ追跡できる。今回の下流作業に影響しない未確定判断は残り得る。 |
| `部分進行可能` | 未確定判断に依存する範囲と、独立して進められる非空の範囲を分離でき、独立する下流判断と許可された作用を進められる。 |
| `要確認` | 未確定判断が今回必要な全範囲、先行する許可、または不可欠な契約判断へ影響し、独立して進められる範囲がない。 |

`部分進行可能` では、進める項目と停止する項目を未確定判断へ対応させる。`要確認` では、確認済みの項目を維持し、判断結果の回答先と、回答後に再開する下流判断を示す。

### Phase 5: 訂正時の再評価範囲を決める
根拠の訂正、置換、競合の解消によって項目が変わる場合は、次の依存方向で再評価対象を決める。

| 変わった項目 | 再評価する下流判断 |
| --- | --- |
| 利用目的 | 下流へ渡す項目と粒度。 |
| 判断主体または権限 | その主体の判断に基づいて確定した項目と、依存する下流判断。 |
| 変更目的 | 変更対象、適用範囲、契約の変更関係、維持する契約、作業対象外、許可、受け入れ条件、実現制約、内部技術契約、候補手段、テスト、検証。 |
| 変更対象、適用範囲、契約の変更関係、維持する契約、作業対象外 | 影響する許可、受け入れ条件、実現制約、内部技術契約、候補手段、テスト、検証。 |
| 許可 | その許可に依存する作用、副作用、作業手順、実装、テスト、検証。 |
| 受け入れ条件 | その条件に依存するテスト、検証、受け入れ判定。 |
| 確定済みの実現制約または候補手段 | その制約または手段に依存する内部技術契約、手段選択、検証。 |
| 観測または検証結果 | 関係する命題を `$claim-grounding` で再評価し、更新された根拠化結果から影響する項目を再構成する。 |

訂正された項目から独立していることを根拠対応から確認できる下流判断は維持する。変更対象の同一性、適用範囲、または項目間の対応自体が変わった場合は、影響する範囲を根拠化結果と指示対象の対応から再構成する。

### Phase 6: 下流へ渡す
他のスキルから適用された場合は、フレーミング結果のうち、その作業の判断、成果、停止、または再評価を変える項目、未確定判断、進行状態を渡す。利用者向け出力には呼び出し元の出力契約を適用する。

利用者が変更整理そのものを求めた場合は、確認済みの項目、未確定判断、進行状態、再評価対象を表または短い箇条書きで返す。未確定判断は、判断対象、判断主体、必要情報、影響項目、回答先をそれぞれ判別できる形で示す。

## 完了条件
- 変更目的、変更対象、適用範囲、契約、許可、受け入れ条件を、それぞれの判断主体、権限、適用範囲を示す根拠へ追跡できる。
- 契約変更、維持する契約、作業対象外、確定済みの実現制約、候補手段がそれぞれの役割を保持している。
- 現状観測と例示が、確認済みの根拠の役割と範囲で使われている。
- 受け入れ条件が各契約変更の完了状態を表し、検証方法を所有する下流作業へ渡せる。
- 根拠から確定できない項目が、判断対象、判断主体、必要情報、影響項目、回答先を独立して持つ未確定判断へ対応している。
- 未確定判断から下流判断への依存関係によって進行状態を判定できる。
- 訂正または置換がある場合は、依存する下流判断と維持できる下流判断が分かれている。
- 内部技術契約、実現手段、テストケース、検証方法の決定が、それぞれを所有する下流作業の責務として残っている。
