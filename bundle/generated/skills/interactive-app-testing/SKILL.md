# interactive-app-testing

## 目的

固定済みの実行契約を実行可能な経路へ具体化するか、変更または成果物を利用者経路で実際に使う有限の確認範囲を変更リスクと確認目的から選定して実行する。確認した範囲、比較結果、候補所見、再現状態、未確認範囲、スクリーンショットや録画などの共有可能な証拠を、一つの対話的テストセッションの成果として残す。

対話的テストの結果は、対象版と確認条件を伴う範囲付きの観測である。確認した範囲で候補所見を観測しなかった場合も、対象全体に不具合が存在しないことや、変更を受け入れられることは保証しない。

## 責務境界

このスキルは、固定済み実行契約の実行経路への具体化、または固定済み実行契約がない場合の変更リスクからの利用者経路と探索範囲の選定、対象アプリの操作、表示と状態の観測、再現確認、媒体証拠の取得、比較結果、確認範囲と候補所見の記録、共有用の証拠説明を所有する。

製品契約、受入条件、許可は、それぞれの権限ある所有者が定めた入力として使う。候補所見の欠陥としての採否と重要度、原因診断、仕様または修正方針の決定、修正案、実装、自動テスト成果物、変更全体の受入判定は扱わない。証拠の説明と共有候補は作成できるが、画像や録画のアップロード、プルリクエスト、Issue、レビューコメントへの投稿または更新は、投稿先、内容、共有範囲、許可が確定した別の作用として扱う。

別の成果責務が必要な場合は、その責務へ渡す観測、証拠、不足する判断、再開条件を返す。このスキル内で原因、仕様、修正方法を補完しない。

## 入力

作業を始める前に、利用目的に必要な次の入力を確認する。

| 入力 | 確認する内容 |
| --- | --- |
| 対象 | アプリ、ビルド、コミット、版、URL、実行個体、環境を一意に識別できる情報。 |
| 確認目的 | 固定済み経路の実行と証拠取得、変更レビュー、引き渡し前の確認、既知問題の再現、修正後の再確認、探索的な確認など、セッションが答える問い。 |
| 比較基準 | 比較を行う場合に使う、権限ある製品契約または受入条件、表示、操作、状態遷移、利用者経路の確認用命題と、その出所および適用範囲。 |
| 既知の候補所見 | 再現対象となる候補所見の種別、元の対象版、観測条件、証拠、採否の状態。 |
| 変更リスク | 変更箇所、影響し得る利用者経路、接続する状態、過去の採用所見。 |
| 固定済み実行契約 | 別の作業で実行目的、対象版、操作主体、開始状態、利用者経路、必要な表示と状態の観測、証拠、許可作用、resetまたは隔離、後始末、実行上限が確定している場合の契約。 |
| 実行環境 | 操作、画面取得、録画、ログ、トレース、状態取得に利用できる能力と、その利用条件。 |
| 許可 | 対象、アカウント、データ、外部状態、許可された副作用、共有範囲。 |
| 状態管理 | 開始状態、テストデータ、seed、reset または隔離、失敗時を含む後始末と、その確認方法。 |
| 証拠管理 | 保存先、保持範囲、秘匿情報または個人情報のマスキング、共有予定先と共有許可。 |
| 実行上限 | 時間、反復回数、探索範囲、停止条件。 |

比較基準に異なる役割の発話、仕様、仮説、観測が混在し、現在の地位または適用範囲を入力から直接確定できない場合は、操作計画を作る前に `$claim-grounding` を適用する。権限ある製品契約を確認できない観測を、契約違反の根拠には使わない。

## フロー

### Phase 1: セッション契約と開始前ゲートを確定する

対象アプリへ作用する前に、次をすべて確認する。

- 対象の版と実行環境を識別できる。
- 必要な操作、観測、画面取得、録画、ログ、トレースを実行環境が提供する。
- 対象、アカウント、データ、外部状態、副作用に対する許可がある。
- 開始状態、reset または隔離、後始末と、その確認方法が確定している。
- 証拠の保存、マスキング、保持、共有の範囲が確定している。
- 確認目的、実行上限、停止条件が確定している。
- 固定済み実行契約を使う場合は、その対象版、経路、観測、証拠、許可作用、後始末を追える。
- 固定済み実行契約を使わず比較を行う場合は、製品契約と確認用命題の区別が確定している。

比較基準がある場合は、次の役割へ分ける。固定済み実行契約が操作と証拠取得だけを求める場合は比較基準を補完せず、操作、表示、状態、媒体証拠を実測として返す。

| 比較基準の役割 | 扱い |
| --- | --- |
| 権限ある製品契約または受入条件 | 実測との比較結果を残す。不一致は `contract-mismatch` の候補になり得る。 |
| 確認用命題 | 表示、操作、状態遷移、利用者経路の実測との比較結果を残す。不一致だけでは候補所見にしない。 |

既知の候補所見は比較基準ではなく、再現確認の対象である。Phase 2で再現条件を定め、Phase 5で再現状態を返す。

必要な能力または許可は、ホスト、対象リポジトリ、操作ツールの現在有効な契約から確認する。特定のブラウザー、デスクトップ操作、ゲームエンジン、コマンドの存在を前提にしない。開始前ゲートを確認するための読み取り専用の状態取得は、その操作手段の契約と許可に従って行い、`setup` または `user-route` の成立証拠には使わない。

開始前ゲートの条件をすべて満たした場合は、Phase 2へ進む。一つでも条件が不足する場合は、不足を補うために本番データまたは共有状態へ推測で作用せず、対象へ作用しないままPhase 5へ進む。Phase 5では、比較対象がある場合の比較結果 `not-assessed`、セッション結果 `blocked`、不足する能力、許可または判断、影響する確認範囲、再開条件、後始末が不要であることを確定する。ツール、環境、データ、reset、観測面の制約が原因なら、候補所見 `execution-limitation` も確定する。

### Phase 2: 有限のセッションを設計する

固定済み実行契約を受け取った場合は、その対象版、操作主体、利用者経路、観測、証拠、許可、後始末、上限を今回の確認範囲として使い、実行可能なsetup、wait条件、観測点、resetと後始末へ対応させる。契約の意味や範囲を変更せず、実行不能または競合する条件は開始前ゲートの不足として返す。

固定済み実行契約がない場合は、完全な操作列を入力として要求せず、次の優先順位で時間または反復上限に収まる確認範囲を選ぶ。

1. 変更された利用者経路と、その経路に対応する製品契約または比較命題。
2. 変更が接続する前後の状態遷移。
3. 主要な正常経路。
4. エラー、停止、復帰、保存、再開など、影響と回復コストが高い境界。
5. 過去に採用された所見と、その修正箇所。
6. 残る上限内で、変更周辺の未知の問題を探す探索的な操作。

各経路について、開始状態、操作意図、`setup`、実際の利用者経路である `user-route`、待機条件、観測点、必要な証拠、停止条件を定める。比較を行う場合は比較基準も対応させる。直接API、状態注入、fixture、seed設定などの準備は `setup` とする。`setup` で直接成立させた状態を、`user-route` が成立した証拠として扱わない。

同じ対象を複数回実行する場合は、再現性を確認する目的、各反復を識別する条件、同じ開始状態へ戻す方法を先に定める。結果が変動した場合は、成功した実行だけを選ばず、各実行条件と観測結果を残す。

有限の確認範囲、各経路の実行条件、証拠、停止条件を確定したら、Phase 3へ進む。

### Phase 3: 操作、観測、証拠取得を反復する

各経路を次の順で実行する。

1. 対象版、環境、開始状態、利用する操作能力、証拠取得の開始状態を記録する。
2. `setup` を実行し、開始状態が成立したことを観測する。
3. 各段階を `action → wait → observe` の順で実行する。
4. 操作、待機条件と結果、実測、証拠を同じ段階へ対応付け、比較基準がある場合はその基準も対応させる。
5. 計画した経路、探索、再現確認を実行上限または停止条件まで続ける。

操作では、利用可能な場合は座標などの不安定な識別より、対象が提供する安定した識別子、アクセシビリティー情報、意味を持つ操作契約を優先する。固定時間の待機より、状態、事象、画面、ログなどの観測可能な終了条件を優先する。

スクリーンショット、録画、ログ、トレース、状態取得は、それぞれが直接示す範囲を記録する。画面証拠だけから内部状態を断定せず、内部状態だけから利用者経路の表示または操作成立を断定しない。秘匿情報または個人情報を含む証拠は、保存または共有の前に確定した扱いを適用する。

候補所見になり得る観測があっても、後続操作が無意味または危険になる場合を除き、自動的にセッション全体を停止しない。停止した場合は、停止条件、最後に完了した段階、現在状態、Phase 4で必要な後始末、再開条件を記録する。

新しいリスクに対応する経路選定が必要で、実行上限が残る場合は、Phase 2へ戻る。同じ条件で再現確認を続ける場合は、定めたresetで開始状態へ戻した後、Phase 3を反復する。計画した確認範囲を完了した場合、停止条件に達した場合、または対象へ作用した後に継続できなくなった場合は、Phase 4へ進む。

### Phase 4: 後始末と終了状態を観測する

対象へ一度でも作用した場合は、成功、候補所見、途中失敗、停止条件のいずれでPhase 3を終えた場合も、確定した後始末を実行する。後始末の各作用も `action → wait → observe` で進め、終了状態、残存データ、実行中の処理、証拠収録の終了状態を確認する。

後始末を完了し、終了状態を観測したらPhase 5へ進む。安全な後始末を完了または確認できない場合も、実行済みの作用、現在状態、影響、再開条件を記録してPhase 5へ進む。Phase 5では、セッション結果 `blocked` を確定し、ツール、環境、データ、reset、観測面の制約が原因なら、候補所見 `execution-limitation` も確定する。

### Phase 5: 結果を分類して成果を作る

Phase 1から受け取った不足、またはPhase 3の実測とPhase 4の終了状態から、比較結果、候補所見、再現状態、セッション結果の順に分類する。これらは別の結果であり、一つを別の結果の代わりに使わない。

#### 比較結果

比較対象として受け取った各製品契約、受入条件、確認用命題について、次のいずれかを返す。比較基準を受け取っていない場合は比較結果を作らない。

| 状態 | 成立条件 |
| --- | --- |
| `met` | 確認した条件と範囲で実測が比較基準と一致した。 |
| `not-met` | 確認した条件と範囲で実測が比較基準と一致しなかった。 |
| `indeterminate` | 関連する操作は実施したが、観測の競合、証拠不足、条件の不安定性により比較できない。 |
| `not-assessed` | 関連する操作または観測を実施していない。 |

比較結果には、比較基準の役割、出所、適用範囲、実測、証拠を対応させる。権限ある製品契約または受入条件との比較結果も、確認した経路の観測であり、変更全体の受入判定ではない。確認用命題が `not-met` であることだけを、候補所見または `findings-observed` の根拠にしない。

#### 候補所見

候補所見を記録する場合は、必ず次のいずれか一つの種別と成立条件へ対応させる。該当する種別がない観測は、比較結果または操作と観測へ残し、型のない候補所見を作らない。

| 種別 | 成立条件 |
| --- | --- |
| `contract-mismatch` | 権限ある製品契約または受入条件と実測が一致しない。 |
| `anomaly` | クラッシュ、停止、状態矛盾など、製品契約の確定を待たず再確認が必要な異常を観測した。 |
| `execution-limitation` | ツール、環境、データ、reset、観測面の制約によって確認範囲が制限された。 |

すべての種別は対話的テストによる候補所見である。欠陥としての採否、重要度、対応範囲はレビュー責務または製品所有者が判断する。

次の決定表に従い、比較結果と候補所見を分ける。

| 観測条件 | 比較結果 | 候補所見 |
| --- | --- | --- |
| 権限ある製品契約または受入条件と実測が一致しない。 | `not-met` | `contract-mismatch` |
| 確認用命題と実測が一致しないだけである。 | `not-met` | なし |
| クラッシュ、停止、状態矛盾を観測した。 | 対応する基準ごとに判定する。 | `anomaly` |
| ツール、環境、データ、reset、観測面の制約で確認が制限された。 | 対応する基準を `indeterminate` または `not-assessed` とする。 | `execution-limitation` |

#### 再現状態

既知問題に対する再現確認は、セッション結果および候補所見と分け、次のいずれかで表す。

- `reproduced`
- `not-reproduced-under-covered-conditions`
- `not-assessed`

`not-reproduced-under-covered-conditions` には、対象版、開始状態、経路、実行回数、観測範囲を対応させる。問題の不存在や修正完了の保証には使わない。

#### セッション結果

一つのセッション結果を、次の優先順位で決める。

| 優先順位 | 状態 | 成立条件 |
| --- | --- | --- |
| 1 | `blocked` | 必須能力、許可、開始状態、安全な後始末、証拠管理の不足により、意図した確認を開始または継続できない。 |
| 2 | `inconclusive` | 操作は実施したが、セッション全体の観測の競合、証拠不足、条件の不安定性により範囲付き結論を確定できない。 |
| 3 | `findings-observed` | 一件以上の型付き候補所見を証拠付きで記録した。 |
| 4 | `no-findings-observed-in-covered-scope` | 定めた確認範囲を完了し、その範囲では型付き候補所見を観測しなかった。 |

`no-findings-observed-in-covered-scope` は、すべての比較結果が `met` であること、対象全体の無欠陥、変更全体の受入成功を意味しない。対象版、環境、経路、実行時間または反復回数、未確認範囲を必ず伴わせ、比較対象がある場合は比較結果も伴わせる。

#### 成果

成果には、利用目的に必要な次の情報を含める。

| 成果 | 内容 |
| --- | --- |
| セッション情報 | 対象版、環境、アカウントとデータの範囲、seed、表示条件、操作および収録能力、実行時点。 |
| 確認範囲 | 選んだ経路、探索範囲、反復回数、完了した範囲、未確認範囲。 |
| 操作と観測 | `setup` と `user-route` の区別、各段階のaction、wait、observe、実測、証拠参照。比較対象がある場合は比較基準。 |
| 比較結果 | 比較対象がある場合の、比較基準の役割、出所、適用範囲、状態、実測、証拠。 |
| 候補所見 | 種別、観測条件、再現手順、対象範囲、証拠、未確定事項。 |
| 再現状態 | 既知問題、再現状態、対象条件、各実行の結果。 |
| 媒体証拠 | スクリーンショット、録画、ログ、トレース、状態取得と、それぞれが直接示す範囲。 |
| 範囲付き結論 | セッション結果、実測、候補所見、未確認範囲と、比較対象がある場合の比較結果を、対象版と実行条件へ限定した命題。 |
| 後始末 | 実行した作用、確認結果、残存状態。 |
| 共有用説明 | プルリクエストまたは引き渡しへ利用できるMarkdown、キャプション、証拠索引、共有前に必要な作用。 |

共有用説明には `$writing` を適用する。読者、媒体、共有範囲を固定し、各証拠が示す範囲と示さない範囲、候補所見であること、未確認範囲を保持する。ローカルに共有候補を作成したことを、外部共有の許可として扱わない。

候補所見、再現状態、セッション結果、証拠、未確認範囲、後始末と、比較対象がある場合の比較結果を確定したら、対話的テストセッションを完了する。

## 引き渡し

候補所見について製品契約、採否、重要度の判断が必要な場合は、レビュー責務または製品所有者へ渡す。採用された候補所見について、原因、仕様、修正方針が未確定なら設計責務、修正対象と修正後契約が確定しているなら実装責務が必要であることを返す。修正後の対象は、同じ確認目的と、比較を行った場合は同じ比較基準を保持して新しい対象版として再確認する。最終的な受入可否は検証責務へ渡す。

外部サービスへの証拠投稿が必要な場合は、投稿先、本文、添付物、共有範囲、許可、投稿後の確認方法を確定する別の作用として返す。

## 完了条件

- Phase 1からPhase 5までの成立状態と、各Phaseから実際に進んだ先を確認できる。
- 対象版、確認目的、開始状態、実行上限、停止条件を確認できる。
- `setup` と `user-route` を分け、操作、待機、観測、証拠を段階ごとに対応付けている。
- 比較対象がある場合は比較結果を定義済みの状態で表し、候補所見、再現状態、セッション結果と区別している。比較対象がない場合は比較結果を作っていない。
- 候補所見は定義済みの一つの種別を持ち、確認用命題の不一致だけを候補所見へ変換していない。
- 比較対象がある場合は、比較基準の役割、出所、適用範囲と実測を分けている。
- 確認範囲、未確認範囲、各証拠の適用範囲を確認できる。
- 後始末の結果と残存状態を確認できる。
