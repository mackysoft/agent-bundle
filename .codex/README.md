# Codex向け実行設定

このディレクトリは、ホスト非依存のSupervisor、Orchestrator、成果責務をCodexで実行するための設定を持つ。責務の意味と進行規則は `.agents/skills/` と各カスタムエージェントの `developer_instructions` が定め、ここではCodex上の登録、モデル、権限、実行経路を具体化する。

## 実行経路

Supervisorは利用者が選択したCodexタスクで実行する。新しい目的には独立したOrchestratorタスクを割り当て、既存の目的には対応するタスクへ追加情報を送る。Supervisorの実行には、Codex Desktopが提供するタスクの作成、情報送信、状態観測を利用する。

OrchestratorはCodexのサブエージェント実行を利用し、`.codex/config.toml` に登録されたカスタムエージェントから成果責務に対応する実行者を選ぶ。開始済みの実行者への補足、完了後の追加作業、状態確認、中断には、実行中のCodexサーフェスが提供するサブエージェント操作を利用する。

Codexの操作名と利用可能性はサーフェスと版によって変わる。実行時に提供された操作を、タスクの作成、情報送信、状態観測、サブエージェントの開始、補足、追加作業、状態確認、中断の各能力へ対応付ける。必要な能力がない場合は、SupervisorまたはOrchestratorへ利用不能な能力として返す。

## カスタムエージェント

`.codex/config.toml` がカスタムエージェント名と設定ファイルの対応を定める。各 `.codex/agents/*.toml` は、責務のCodex向け説明、モデル、推論強度、サンドボックス、下位エージェントを起動できるかを定める正本である。実行時には、登録された設定ファイルから現在の値を取得する。

`worker`と`explorer`はCodexの同名の組み込みエージェントを、このプロジェクトの責務契約で置き換える。これは意図した上書きである。

すべてのカスタムエージェントは下位エージェントを起動しない。作業分解、並行実行、追加作業、再割当、複数レビューの回収はOrchestratorが行う。

## モデルの選択

モデルと推論強度は実行設定であり、成果責務の名称と意味には含めない。同じ成果責務を別のモデルで実行する必要がある場合は、責務定義を複製せず、Codexの起動設定を変更する。

独立したOrchestratorタスクには、通常の進行管理として `gpt-5.6-terra` と `high` を使用する。目的の内容から設計判断が必要になった場合は、Orchestrator自身が設計せず、`architect`へ割り当てる。

## 許可と実行能力

依頼者が許可した作用と、Codexのサンドボックスまたはツールが実行できる作用は別に確認する。カスタムエージェントは両方が許す範囲で実行する。必要な作用を実行できない場合は、許可または実行能力のどちらが不足しているかを結果へ示す。
