# 専門文書

## 書く対象
- 仕様、契約、制約。
- 判断と根拠。
- 使い方、運用、確認方法。
- 専門用語、設定、手順、エラー、データ。

## 構造
- 文書の目的と読者を先に固定する。
- 仕様、手順、背景、判断基準、例を分ける。
- 正常系、失敗系、制約、未対応範囲を混ぜない。

## 文書間の責務
- 文書ごとに、正本として定める内容と、別の正本を利用して説明する内容を区別する。
- 表現や粒度が異なっても、同じ定義、規則、判断を担う内容を別の文書へ重複して置かない。
- 別の文書が正本を持つ内容は反復せず、この文書の責務に必要な判断、利用、運用の説明と参照だけを置く。

## 時間上の責務

仕様、契約、設計、計画の正本には、その成果物が定める有効な内容と、対象領域の事象に固定された順序または条件を記述する。
作業中の状態や進捗の正本は、進捗管理表、Issue、マイルストーン管理情報など、その情報を更新する成果物が持つ。
別の成果物が状態や進捗を報告または要約する場合は、利用した正本または出典と観測時点を示す。

| 情報の基準 | 扱い |
| --- | --- |
| 執筆時点または閲覧時点だけを基準に変わる状態 | 成果物が正本として記録するか、別の正本に基づいて観測時点付きで報告または要約する責務を持つ場合だけ置く。 |
| 日付、版、識別されたマイルストーンの境界または達成事象、対象領域の事象に固定された期間、順序、条件 | 成果物の責務と読者の判断に必要な場合は保持する。 |
| 対象領域の実行時事象に対して相対的に定義された現在値、初期状態、状態遷移 | 執筆時点または閲覧時点との関係ではないため、仕様または説明に必要な場合は保持する。 |
| 観測時点に取得した実行対象の値または状態 | 状態を記録、報告、要約する責務を持つ成果物だけに、利用した正本または出典と観測時点を示して置く。実行対象の値であることだけを仕様へ残す根拠にしない。 |

継続して更新する正本で現在有効な属性を示す場合は、執筆時点との関係を属性名へ加えず、属性と値を直接記述する。
段階によって属性または値が異なる契約では、段階を日付、版、識別されたマイルストーンの境界または達成事象、対象領域の事象へ結び付ける。
現在選択されているマイルストーンは進捗状態であり、それ自体を固定基準として扱わない。

## 専門語彙
- 専門用語、識別子、設定キー、スキーマ語彙は、対象媒体の表記規則に従う。
- コマンド、ファイルパス、コード識別子はコード表示にする。
- 一般語や説明語を、意味ありげな英単語の羅列として扱わない。
- 専門語彙と一般語の境界を揃える。
- コード、差分、ログ、設定ファイルの断片はコードブロックで示す。

## 例とスニペット
- スニペットは、読者が実行または照合できる粒度にする。
- 例は仕様そのものではなく、仕様の理解を助ける補助として置く。
- 例外や制約が重要な場合は、例の外で明文化する。

## 補足
- 本筋から一段外れる補足は、本文に並べず脚注または補足節へ降ろす。
- 本文に必要な定義や制約は、脚注へ逃がさない。
- 仕様を反復するだけの説明は避け、読者が利用、判断、運用に使う説明へ寄せる。

## 更新
- 既存文書を更新する場合は、既存の責務範囲を守る。
- 新しい説明を足す前に、既存の節へ統合できるか確認する。
- 古い説明が残る場合は、矛盾した説明を併存させない。
